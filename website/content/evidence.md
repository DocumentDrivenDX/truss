## Published release evidence

The v0.0.49 row records the current managed-grants release. The remaining v0.0.48 receipts below document its predecessor and retain their original scope.

Truss `0.0.49` adds managed platform-grant policy and install API/CLI support to the v0.0.48 HF baseline. Its published evidence covers native manifest SHA-256 prefix `288801f7`, four admitted migration sources (106 cases), the HF62 independent corpus, the managed 21-module/130-test gate, the public Weft 0.4.51 cohort from compiler source revision `55715373…`, and selected installed Linux/macOS qualification. Actual Lakebase acceptance remains a separate qualification.

Only the latest application runtime is supported. The latest tool provides offline, explicit transactional forward migration for the admitted UMF `0.10` sources: v0.0.44, the shared v0.0.45/46 lineage, v0.0.47 and v0.0.48 on PostgreSQL `18.6`. Admitted databases retain a forward route without a release-age cutoff. Startup never upgrades or resets a database.

## What remains open

Broad unselected native discovery remains incomplete, and general performance budgets remain provisional. ABI1.2 indexes exact string/boolean equality and eligible single required-string-key pages for populations above10,000 rows. Complete candidate and byte limits still apply before residual filters and `LIMIT`; numeric, temporal, composite and larger-key routes use the bounded complete fallback. Complete-entity relationships remain capped at100 related keys. The retained million-object stress result exceeds the source cap for its full SQL list and does not establish unrestricted large-source queries. The v0.0.49 migration and independent corpus checks cover only the linked source tuples and selected cases; larger database migration capacity and additional restore profiles need separate qualification.
