<section class="thesis" aria-label="Design principles"><div><span class="label">01 / Evolve the model</span><h3>Catalog rows.<br>Not migration churn.</h3><p>Types, properties and relationships are catalog rows in one fixed layout: no table, column or index per type.</p></div><div><span class="label">02 / Keep the meaning</span><h3>Every value<br>deserves its history.</h3><p>Properties and edges are the unit of change. A journal records per-property history in the same transaction, and unrecognized content is retained.</p></div><div><span class="label">03 / Show the boundary</span><h3>Know which<br>rules actually hold.</h3><p>For each UMF assertion Truss reports whether the database, the engine or nothing enforces it.</p></div></section>
<section class="status"><span class="label">Release {{< param "version" >}}</span><h2>Experimental, and tested on Linux.</h2><p>Truss {{< param "version" >}} is the Python package <code>umf-truss</code>: catalog registration, typed object and edge mutation, key lookup, pages, history, imports, an acknowledged change feed and Weft queries, on PostgreSQL 18.6 only. Temporal values and bulk job control are experimental. Continuous integration runs the Python test suite and the <a href="start/">quickstart</a> on Linux. See the <a href="https://github.com/DocumentDrivenDX/truss/blob/main/CHANGELOG.md">changelog</a> and <a href="https://github.com/DocumentDrivenDX/truss/blob/main/ROADMAP.md">roadmap</a>.</p></section>
