# Reference current-policy composition handoff

Compose CONTRACT-005's existing public disclosure and private observer policies as one installation unit. This selects policy admission/order and failure behavior, not deployed CREATE POLICY statements or native role identities. The optional baseline module-isolation fragment cannot supply current document-qualified or expanded-store protection.

## Ordinary disclosure and private completeness

For each exposed RLS relation/command, enumerate the complete actual applicable policy set, native role applicability and effective relation/column privileges. Ordinary disclosure requires the native access privilege, at least one permitting applicable permissive policy, and every applicable restrictive policy. Validate the resulting predicate against original document/module/relationship/endpoint or retained owner-union requirements. A broad permissive policy cannot erase a restrictive filter; an allow-only restrictive policy cannot create access when no permissive policy admits it.

Private integrity observation uses the existing exact protected observer-owner policy and narrow SELECT rights. Every applicable restrictive policy must independently admit that observer's complete selected scope; one filtering host policy makes complete observation unavailable. Do not disable FORCE RLS, acquire BYPASSRLS, grant application ownership or change host policy implicitly to make the count pass. Tables without selected RLS require their separately admitted complete privilege/disclosure procedure. Missing or filtered evidence never becomes zero degree, absent property or clean catalog scan.

The public predicate uses original native actor custody and current qualified grants. Private policy applicability may use the admitted definer's current_user to identify its internal responsibility, but that value cannot authorize the outer caller's result. Ordinary roles must have no inheritance/SET/admin/wrapper path that acquires observer scope or exposes its results. Observe every transitive invocation and diagnostic path; a denied direct helper call alone cannot prove this separation.

## Installation and transition order

1. Under original installation/policy exclusion, enumerate actual relation ownership/RLS flags, command policies and role applicability, relation/column privileges, definer/private callers and host restrictions. Include views, owners, inherited/SET roles, defaults, PUBLIC, administration and restore paths.
2. Derive the complete intended protected policy/grant delta from original advertised surfaces and current qualified owner meanings. Every relation/command has explicit public disclosure, private completeness or forbidden access disposition. No family label grants all 46 stores to readers.
3. Install/reconcile exact policies, private rights and participating helpers atomically with their original bodies/dependencies. Recollect actual definitions/applicability and effective privileges; compare against the complete intended inventory before readiness.
4. Independently prove public authority intersections and private complete observation, including restrictive-policy interaction and hidden corrupt data. Authoritative observations and native probes follow implementation; source policy text cannot prove the result.
5. Publish only after full correspondence. Confirmed rollback preserves the prior admitted profile; unknown administrative settlement retains original recovery. Policy/role/owner/body changes invalidate affected capabilities through the existing generation/current-authority coordination.

## Independent composition controls

PC-01: SELECT privilege present, no applicable permissive policy, permissive deny, restrictive deny and multiple permissive/restrictive combinations. Require actual native policy semantics and complete applicable-policy inventory.

PC-02: a restrictive host policy filters the observer's hidden required edge or row-home state. Refuse private-completeness/readiness rather than report within-limit/absence. Add an observer permissive allowance and verify that it cannot override the restrictive filter.

PC-03: ordinary role inherits a policy-applicable role, can SET into an internal owner, invokes an elevated public wrapper or receives leaked private diagnostics. Reject the affected protected profile even if its direct helper ACL looks narrow.

PC-04: owner bypass, FORCE RLS difference, BYPASSRLS/superuser and non-RLS relation access. Inspect each actual path; never classify administrative bypass as ordinary-reader/writer enforcement.

PC-05: qualified same-name modules in distinct documents, cross-module edges and retained historical/deleted owners. Every advertised read surface preserves its complete original authority requirements; a private integrity success supplies no wider disclosure.

These controls remain planned under STP-045 and the original isolation/read/concurrency corpus. PostgreSQL 17's [row security documentation](https://www.postgresql.org/docs/17/ddl-rowsecurity.html) defines policy combination, owner/bypass and command boundaries. The complete current native tuple, policies/helpers/role graph and authority/transaction/resource evidence remain required before installed support.
