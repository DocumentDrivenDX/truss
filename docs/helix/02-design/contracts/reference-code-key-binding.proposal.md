# Reference code and key binding proposal

Original fields are Account.code and Item.code in document truss.integration.account-items.v1/module integration, at /modules/0/elements/0 and /modules/0/elements/1 in the [field inventory](reference-account-items-field-inventory.proposal.json). Each is required scalar string/cardinality one and is the sole component of its owning Record's authored primary key by-code. These are distinct field and key identities despite equal display names or value bytes.

Preserve exact Unicode string content and absence/null/empty distinctions. Required code cannot be absent or present null. Empty text is a present string and must follow the original domain/key admission; no invented nonempty constraint follows from the example codes. Do not case-fold, trim, pad, normalize Unicode or stringify nonstring values. Truss's selected U+0000 refusal and native/transport limits remain explicit unsupported-value rules; the original UMF string definition is not silently rewritten to conceal those limitations.

Portable key bytes come from the existing admitted UMF encode-core-key-tuple operation 2.0.0 / umf-key-tuple-v1 under the complete original Record/key/field definition. The [five independent byte witnesses](../../04-build/evidence/design-audit/reference-account-items-key-tuples.json) already retain Account account-α, Item item-b/c/d and identical account-α payload under Item, plus refusal controls. Truss supplies native custody/enforcement and does not implement that encoder again. Preserve exact original tuple bytes and definition context; a digest or text serialization cannot replace the full tuple.

Native key lookup/uniqueness/reservation scope includes the complete admitted qualified owner type and owner-local key identity in addition to tuple bytes. Account/by-code and Item/by-code with equal tuple payloads must remain distinct. Route hashes serialize/rout candidates only; independently compare full original namespace/preimage/key bytes before equality, admission or lookup. Preserve existing key/reservation policy and lifecycle evidence; code mutation cannot bypass current key enforcement, retired reservations or full final graph invariants.

The reference comparison proposal uses exact string equality with explicitly admitted native C comparison semantics. Select exact type/operator/collation/encoding dependencies and prove Unicode/padding behavior under the real native build before registration. Portable tuple byte order is not automatically business string order or query cursor order. Any requested ordered read must use its separately admitted comparator; this key binding supplies no implicit query order.

Select each field's physical home and original string/value/key codec profiles before activation. No props fallback, native cast to text, different field owner or matching display name can repair a wrong-home/codec/source observation. Full required owner integrity and exact native descriptors precede public value/key interpretation.

Existing K01–K04 schedules cover concurrent duplicates, same payload across the two key namespaces, mutation/rollback and key/relationship authority composition. Extend their independent corpus with empty text, case differences, trailing spaces and composed/decomposed Unicode, preserving distinctions required by the original equality definition. Native observers record full namespace/preimages and actual guards/settlement; a successful portable UMF receipt alone cannot pass uniqueness or isolation. Explicitly refused U+0000 and unsupported transport values must preserve the original committed graph/key/source/journal state after confirmed containment.

This proposal supplies intended field/key meaning and existing source provenance. Actual native string comparison, complete key producer/guard/security/resource and Weft binding adoption remain open. It does not select a narrower schema, claim all Unicode/native domains supported, or qualify a deployment.
