Preserve exact Unicode string content and absence/null/empty distinctions. Required code cannot be absent or present null. Do not case-fold, trim, pad, normalize Unicode or stringify nonstring values. Truss's selected U+0000 refusal and native/transport limits remain explicit unsupported-value rules; the original UMF string definition is not silently rewritten to conceal those limitations.

The [five independent byte witnesses](../../04-build/evidence/design-audit/reference-account-items-key-tuples.json) already retain Account account-α, Item item-b/c/d and identical account-α payload under Item, plus refusal controls. Truss supplies native custody/enforcement and does not implement that encoder again. Preserve exact original tuple bytes and definition context; a digest or text serialization cannot replace the full tuple.

Native key lookup/uniqueness/reservation scope includes the complete admitted qualified owner type and owner-local key identity in addition to tuple bytes. Account/by-code and Item/by-code with equal tuple payloads must remain distinct. Route hashes serialize/rout candidates only; independently compare full original namespace/preimage/key bytes before equality, admission or lookup. Preserve existing key/reservation policy and lifecycle evidence; code mutation cannot bypass current key enforcement, retired reservations or full final graph invariants.

The reference comparison proposal uses exact string equality with explicitly admitted native C comparison semantics. ## Reference native equality and lookup procedure

Keep two comparisons distinct. Field string equality uses the separately admitted exact text/operator/C-collation profile above. Portable key identity compares the complete UMF tuple bytes plus the complete qualified namespace bytes in the existing `object_key_bucket` and reservation homes. Neither text collation nor decoded JSON equality supplies that binary identity. Bind original bytes through the admitted bytea transport/operator profile; no hex/base64 text comparison, text cast or digest equality replaces it. The original-context/reservation artifacts must independently agree with their original definition/owner and lifecycle, not merely have matching hashes.

For Account/by-code or Item/by-code lookup: admit the complete original Record/key/field and requested string under the source/value budget; obtain tuple bytes from the existing UMF operation; obtain namespace bytes from the admitted qualified owner/key profile; derive routes under the original route profile; collect the complete collision cohort under the existing serialized/current-authority procedure; verify original namespace/key/context bytes and owner/type/key/lifecycle membership; then compare full namespace and tuple bytes. A digest collision is a candidate to inspect, not a duplicate or successful lookup. Do not take the first row, hide malformed cohort members with a value predicate or use a LIMIT to convert incomplete collection to absence.

Zero complete matches permits not-found only after complete admitted visibility, applicability, lifecycle/reservation and retained source correspondence. Exactly one complete live match must bind the same original object/type/key and authorized canonical record before return. Two complete live matches are integrity failure, never arbitrary success. A retained reservation can refuse new use without supplying a live object. Mutation uses the same byte identity and guard order before effect admission; fresh post-lock revalidation remains mandatory and no read-only helper grants write enforcement.

Charge the complete routed cohort and simultaneous original key/context bytes to the enclosing resource account. The declared key-byte column ceiling is not a work budget or permission to materialize an unbounded collision cohort. Native operator, transport, hash-route and guard definitions/security remain exact qualification outputs; this procedure allocates no native identities and changes no 0.12 declarations.

Select each field's physical home and original string/value/key codec profiles before activation. No props fallback, native cast to text, different field owner or matching display name can repair a wrong-home/codec/source observation. Full required owner integrity and exact native descriptors precede public value/key interpretation.

Existing K01–K04 schedules cover concurrent duplicates, same payload across the two key namespaces, mutation/rollback and key/relationship authority composition. Extend their independent corpus with empty text, case differences, trailing spaces and composed/decomposed Unicode, preserving distinctions required by the original equality definition. Native observers record full namespace/preimages and actual guards/settlement; a successful portable UMF receipt alone cannot pass uniqueness or isolation. Explicitly refused U+0000 and unsupported transport values must preserve the original committed graph/key/source/journal state after confirmed containment.

This proposal supplies intended field/key meaning and existing source provenance. Actual native string comparison, complete key producer/guard/security/resource and Weft binding adoption remain open. It does not select a narrower schema, claim all Unicode/native domains supported, or qualify a deployment.

## Concrete native field equality handoff

The [private equality observation](reference-code-equality-observation.proposal.sql) selects two pg_catalog.text operands with explicit pg_catalog.C collation and schema-qualified equality, returning one boolean-as-text observation named equal_text. Source operands are already admitted non-null exact strings for their original Field/home/definition; the query supplies no source validation or owner authority. NULL or unsupported native strings refuse before invocation. The complete result admits exactly one text cell true or false under the actual observed descriptor/completion, with no truthiness, NULL-to-false or abbreviated boolean parsing.

Native registration must retain the exact operand/result types, resolved equality operator and implementation, collation provider/determinism/encoding identity, bool-to-text cast dependencies and server build/settings. Explicit SQL names select the authored dependency request, not an installed OID or verified comparator. Ordinary caller operators, ambient collation/search path and nondeterministic substitute collation cannot participate. This query closes the reference observation form; actual native dependency/security/resource admission remains required.

The [independent equality oracle](../../03-test/reference-code-equality-expected.proposal.json) covers empty text, case, trailing spaces, composed/decomposed accents and supplementary Unicode. These comparisons establish neither portable tuple identity nor ordering, uniqueness, key namespace or whole-owner integrity. UMF continues to own portable key encoding. Account and Item fields using this comparison still have distinct definitions and namespaces; equal field content cannot transfer object/key identity between them.
