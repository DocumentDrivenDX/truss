# CONTRACT-010: Exact recursive value transport

## Numeric codec family correspondence — current draft correction

The JSONB leaf codec schema now requires matching family/decodedCarrierKind pairs: integer/integer or decimal/decimal. A string token storage representation does not turn a typed integer into a decimal or make a numeric-looking string numeric. Both numeric branches still require original numericAdoptionEvidence plus source/native/profile custody; a shape-valid synthetic artifact is not reviewed adoption evidence.

[Seven shape controls](../../04-build/evidence/design-audit/numeric-codec-family-shapes.json) accept matching integer/decimal declarations and refuse cross-family carriers, missing adoption artifact, raw JSON-number storage and a string carrier for decimal. Reproduce with `bun docs/helix/04-build/evidence/design-audit/check-numeric-codec-family-shapes.ts <Ajv2020-module-path>`. The current 0.11 one-string packet still passes its six schema checks. These are draft schema controls only; exact artifact hashes, authored field/domain correspondence, token grammar/facets and native codec behavior remain independently admitted.

Existing source-pinned schemas/Weft receipts retain their original hash scope. This tighter draft cannot be presented as the same bytes as a previously frozen owner schema; a selected numeric binding must pin the corrected source and obtain its own review. No compiler-owned lowering/decoder implementation is changed by this correction.


## Owner decisions — 2026-10-07

Accepted numeric direction: preserve exact authored integer/decimal tokens and reject silent precision loss. The JavaScript facade uses safe number values by default where lossless, bigint for larger integers and an exact decimal carrier preserving spelling. A number supplied for a decimal is admitted only when its actual binary value is exactly representable in the selected declared decimal domain; unsafe integer numbers, out-of-domain values and rounding refuse. Explicit float domains remain separately qualified. Number-origin input cannot recover spelling already lost before admission. Reads preserve original token custody and permit number conversion only with an explicit lossless check.

Reuse UMF's existing integer/decimal/float distinctions, facets, exact literal tokens and portable key semantics. UMF’s public numeric conversion producer and the existing Truss registration are available; consume the pinned APIs and scoped source/browser evidence in [the current numeric adoption handoff](core-numeric-number-view.proposal.md#current-umf-numeric-producer-adoption-handoff--2026-10-08). Shared-resource precharging, complete native correspondence, error translation and signed-zero number-view limits remain explicit qualification boundaries, without duplicating UMF conversion semantics. This accepts the carrier/API direction, not the separate proposed Truss compact decimal key profile or unqualified float/record/native support.


**Version:** proposed truss-value/0.1.0. **Status:** draft; wire transport, not an accepted storage encoding.

## Byte-document custody versus native value admission

The PostgreSQL-bound string restrictions below apply to selected interpreted
values, including nested Truss value strings and map/record names. They MUST NOT
be applied by decoding arbitrary ExactArtifact payload bytes as if those bytes
were a value destined for PostgreSQL text or JSONB. Original source/report/diagnostic
byte custody and native cell admission are distinct contracts.

CONTRACT-003's canonical report byte encoding can escape U+0000 into its original
bytea representation without storing that scalar in a PostgreSQL text cell. A
byte-document codec MAY preserve that scalar under its selected report/source
profile. It MUST still reject invalid UTF-8 and unpaired surrogates, preserve
original bytes independently, and apply the complete interpretation/profile
checks before any native effect. This does not permit NUL in the reference
`text_value` realization or in a PostgreSQL JSONB string. A byte-codec pass cannot
establish that the same text is a supported authored property, key or native name.

Opaque ExactArtifact contents remain untraversed until their own original bounded
interpretation is selected. Integrity checks compare their actual complete bytes
and digest; successful schema validation is neither artifact integrity nor
semantic/authority admission. No codec may remove characters, normalize strings
or regenerate source bytes to make an unsupported native value appear valid.

A preparation codec may retain the original spelling of a schema-valid incoming
report, including whitespace or alternate escapes. That result MUST NOT be
presented as a persisted canonical report artifact. CONTRACT-003's original
artifact loader separately requires exact canonical re-encoding equality and
original report/revision/effect custody; noncanonical spelling refuses that loader.

Independent paired checks preserve original NUL-containing report bytes through
the byte codec while refusing the same decoded scalar in the selected PostgreSQL
text-value path before effects. They separately compare alternate-escaped versus
literal source bytes and require canonical artifact spelling at persistence/load.
The current 39-control Python/TypeScript report experiment establishes shared
wire decisions and original byte preservation only; it supplies no native-cell
or accepted-report qualification.

## Surface

[exact-value-v0.1.schema.json](exact-value-v0.1.schema.json) describes explicit presence and tagged exact values. `{present:false}` has no value; `{present:true,value:{kind:null}}` is present null. The pinned UMF definition decides whether absence/null is allowed. Schema validity alone cannot establish model validity or support.

Integer/decimal/binary/timestamp/string carry exact text. Boolean carries a JSON boolean. Sequence carries ordered values. Map carries ordered key/value entries with unique exact keys; record carries definitionPin and unique fieldId/value entries. Omitted record fields are absent. Duplicate map/field identities reject before interpretation; no last-key-wins. Ordering preserves authored content; model semantics determines whether order is observable. UTF-16 unpaired surrogates and U+0000 reject for PostgreSQL-bound strings at every nested level. Byte parsing rejects duplicate JSON envelope members before ordinary schema validation.

Opaque carries recognized format, exact sourceText and verified SHA-256 of its UTF-8 bytes. It does not silently parse/rewrite unknown semantics. It preserves source content only within the recognized Unicode source format; arbitrary binary source needs a separately versioned carrier. Selected unsupported opaque semantics block required operations, while unselected uninterpreted content may be retained. Digest is integrity, not semantic identity or authority.

## Semantic validation

Resolve definitionPin under the exact model/catalog bundle; missing or wrong-owner pins block. Numeric grammar/facets and native domains, binary canonical base64, timestamp grammar/offset semantics and recursive record/collection types follow the selected versioned profile. Never infer numeric family from string spelling or coerce tagged text into a host number. Decimal lexical identity is distinct from mathematical key canonicalization. Empty sequence/map remains present.

Initial proposed bounds: 16 MiB UTF-8 envelope, depth 128, 100,000 value nodes, 1 MiB scalar text, and 10,000 entries per collection/record. Check bounds during parsing/allocation, not after unbounded materialization. These are draft default limits requiring corpus/owner review; native numeric digit/exponent limits remain independently declared. Failure returns a source path and named limit/type/encoding diagnostic, never a partial successful value or silent truncation.

## Storage and Weft integration

### Temporal fidelity and comparison boundary

For an offset-bearing timestamp, retained transport text preserves the authored offset spelling and fractional precision. Converting it to Date, epoch milliseconds or PostgreSQL timestamptz alone is insufficient for FR-10, because those representations can erase offset/precision. A derived comparison representation may accompany exact text under a declared binding; it cannot replace the round-trip carrier. Database session timezone changes must not alter the authored value returned by direct reads, journals, replay or imports.

Independent fidelity vectors include `2026-10-05T12:00:00.1200+02:00` and `2026-10-05T10:00:00.1200Z`: a profile supporting both must return each original spelling separately even if its instant comparator considers them equal. `2026-10-05T12:00:00.12+02:00` retains its different fractional spelling. These vectors specify retention, not a universal timestamp grammar or key equivalence. A timestamp without offset cannot gain an inferred local timezone; date-only, local-time, interval and native special values require their own declared semantic families rather than being relabeled as offset timestamps.

The selected UMF/native definition governs legal offset forms, calendar ranges, precision, leap-second/special-value support and equality. Unknown selected temporal meaning blocks comparison/key/query support without losing retained content. Weft comparison lowering consumes the reviewed temporal binding and must refuse an unsupported comparator; exact transport alone cannot establish native temporal predicate correctness. Native evidence varies session timezone and timestamp precision, compares raw retained text, and separately verifies any declared instant/key comparator.

This wire representation does not mandate tagged JSONB storage. ADR-006 proposes catalog-directed numeric token strings; mapping must explicitly translate between wire and recognized storage profile. Current JSONB numeric-only rows cannot be certified lexical-exact through this schema. Weft typed descriptors/carriers remain compiler-owned; integration supplies an explicit reviewed conversion, not a replacement Weft schema.

### Direct native timestamp metadata proposal

The fixed page/lookup statements project created_at/updated_at as native text and return DateStyle/TimeZone observations in the same statement. These are private decoder metadata, not new DirectRecord fields or authored timestamp provenance. [PostgreSQL 17 date/time documentation](https://www.postgresql.org/docs/17/datatype-datetime.html) describes output-style/timezone dependence and the loss of original timezone spelling in timestamptz storage. A driver Date, guessed locale or current application timezone cannot establish exact native metadata decoding.

Bind these observations and actual server/type/codec version to the original read profile. Decode native text through the explicitly registered grammar/range/calendar/precision/special-value profile, then serialize the permitted public createdAt/updatedAt without rounding. Preserve original raw observation and settings under private custody where required. Missing/incompatible settings or unsupported native meaning refuses complete record interpretation; it cannot become null, an empty value or a silently narrowed timestamp range. A profile must explicitly address extended years/era markers and infinity families rather than assuming every legal native timestamp is an ordinary four-digit RFC 3339 value. Those complete mappings remain authoring/adoption outputs.

The read does not SET DateStyle/TimeZone or alter the caller's session to force a convenient format. Original executor arbitration excludes competing configuration changes on the same connection during admitted observation; host connection/role replacement requires fresh context admission. Compare resulting native instants and exact microsecond metadata across qualified session-format variations separately from authored timestamp fields, whose original offset/fractional spelling remains retained under the exact-value profile. Metadata rendering is not evidence of authored timezone or commit time. Charge text/settings/framing/decoder buffers to the same original read resource ledger.

### Direct bucket binary projection proposal

The fixed bucket lookup now projects complete matched namespace/key/context through qualified pg_catalog.encode(bytea,'hex') into explicitly named private *_hex columns. [PostgreSQL 17's binary conversion documentation](https://www.postgresql.org/docs/17/functions-binarystring.html) specifies lowercase hex output with two digits per byte. This selects one native observation carrier without changing original byte identity, key equality, stored bytea or public ExactArtifact base64. It avoids an implicit driver Buffer/bytea representation in this draft; actual text framing and allocation still require qualification.

The private decoder admits only even-length lowercase hex, with no prefix, padding, whitespace or alternate alphabet, and bounds encoded length before allocating decoded bytes. Check complete decoded length and independently compare original namespace/key/source artifact bytes and profile/domain custody. Do not decode through host numeric accumulation, UTF-8 text interpretation of arbitrary bytes or hash-only equality. Empty bytes are legal only where the selected field/profile permits them; nonempty context/lineage fields cannot accept empty hex. Charge hex's exact twofold expansion, decoded copies and repeated comparison to separate native carrier and original owned-byte limits. SQL/native decoder leniency cannot expand the registered carrier grammar. All matched fields remain private under CONTRACT-005's protected read boundary.

### Direct native JSONB text decoder proposal

CONTRACT-004's fixed page/lookup statements now project props and object retained as JSONB text. Admit this as a bounded native rendered carrier before constructing a host object; the driver must not preparse it through ordinary host JSON numbers. The registered decoder consumes exact scalar tokens without numeric coercion, validates map/object shape and resolves each property/member through the actual pinned catalog/storage/value profile. A catalog-directed numeric token string, literal string and opaque content are distinct meanings; string spelling alone cannot select the family. Nested record/collection interpretation needs complete original definition correspondence, not a top-level scalar guess.

For the proposed signed native catalog profile, each props member name must itself be canonical signed int32 decimal text: exactly `0`, or an optional minus followed by a nonzero digit and remaining decimal digits, within the signed native domain. Preserve the exact admitted key text as the lookup identity. Refuse plus signs, leading zeros, negative zero, whitespace, exponent/decimal notation and out-of-range values; do not parse permissively and merge them with another member. JSON string escapes are decoded under the bounded scalar parser before this grammar is applied; duplicate decoded member names refuse before map construction. Native numeric ordering/range and exact text identity remain separate from JSON array positions or host-number object access.

Resolve every admitted property ID through the complete selected record-category/owner/definition and written-revision encoding mapping. A globally existing ID belonging to another owner/category is not a valid field here. A missing original mapping, unsupported retired-definition interpretation or incompatible current reinterpretation refuses complete observation; it cannot drop that property, relabel it as retained or use a same-named current field. Apply the resolved scalar/collection/record codec to that member only after identity correspondence. Full decoding consumes every member, including entries omitted by a convenience caller projection; otherwise the decoder cannot certify the complete DirectRecord.

Retained member names follow their separate exact unknown-name/presence profile, not property-ID grammar. A retained name `1`, `01` or `__proto__` remains its own admitted name and does not address a defined property or mutate a host prototype. Use inert entry/dictionary storage with no inherited-member lookup, setters, coercion callbacks or code execution; output follows the existing explicit retained carrier. Apply the same inert name handling to admitted row-home literal map keys during RF04 reconstruction, while retaining their separate original map-definition/slot semantics. Empty map keys and names equal to host prototype members remain literal data; they never resolve through authored record-field or signed property-ID lookup. Require full-key duplicate checks before constructing output, including exact Unicode spelling; routing hashes or normalized strings cannot merge different keys. Preserve exact Unicode spelling and case without normalization. Any selected name/Unicode/storage limitation refuses explicitly under the containing observation profile rather than renaming the field. Charges include decoded member names, duplicate/correspondence tables and all nested codec work under the original D0–D7 ledger.

JSONB text is the native value's current rendering, not the original authored JSON/source bytes. It cannot recover lexical spelling already discarded by legacy storage, duplicate source members or original document whitespace. Numeric-only legacy rows remain unavailable for required lexical-exact claims unless a separately qualified retained source/value mapping proves the missing correspondence. Do not wrap their rendered token in the exact wire and claim lossless authored round-trip. Original source/opaque artifacts remain separately archived; native text is not a substitute.

SQL NULL retained is absent native column state; JSON null within an admitted map is present null under its selected value profile. Empty object, empty collection, absent property and null remain distinct. Decode every member or explicitly refuse the selected profile; no unknown property/key/tag may disappear. Verify opaque bytes/text against original artifact/hash without invoking document-selected code. Canonical public serialization and native JSON escaping/UTF-8 text are charged separately under the original containing read/resource profiles, including parser buffers and copies. Unsupported numeric/temporal/native meaning is profile unavailable, not not_found or an empty map.

Plan the reusable bounded storage-to-wire decoder beneath reads/decode-record.ts and other qualified history/mutation consumers. It must not fork UMF validation or Weft's compiled result decoder ABI. Native text framing, complete storage-profile metadata, duplicate/token grammar, canonical value output and selected runtime/browser qualification remain required outputs. Source-preservation checks establish the SQL casts only, not decoder behavior.

Mutation result/journal/source envelopes can reference this presence carrier only after their versions are reconciled. Unknown extension semantics and additional native scalar families require explicit carriers/profile changes; this schema does not redefine the full PRD as these tags alone. No new carrier may be silently downcast to string and claimed supported.

### Exact numeric source/native correspondence procedure

NX01–NX06 applies the existing [ADR-006 compact decimal tuple](../adr/ADR-006-exact-numeric-value-carriers.md#candidate-compact-decimal-equality-profile) to admitted integer/decimal source-versus-native observation equality. It is a producer/resource/refusal procedure for that underlying mathematics, not a competing normalization definition or a newly accepted storage/key profile. It grants no grammar, facet, key, ordering or aggregate capability and changes no UMF semantics. The registered original source and native grammar must each supply an exact finite sign/mantissa/exponent interpretation before this procedure applies; an arbitrary string accepted by a host parser or native cast is insufficient. Original lexical bytes remain unchanged in numeric_token and original_source_bytes.

1. NX01 admit original semantic/source/native grammar, facets, exact native domain/descriptor, original token and actual native text observation under the selected context/resource profile. Both complete inputs must be finite and available. Reject source grammar/facet/native representability violations before comparing; equality cannot make an otherwise invalid token valid.
2. NX02 scan each complete admitted token into sign, mantissa digits, fraction digit count and signed decimal exponent. Use bounded exact digit strings and checked bigint counters/exponent arithmetic, never JavaScript number, floating parsing or locale conversion. Charge every scanned input occurrence and retained copy. Grammar-specific separators/sign/exponent rules remain owned by the original selected parser.
3. NX03 only after complete NX01/NX02 admission, remove leading zeros from the concatenated mantissa digits. If no nonzero digit remains, derive the mathematical zero witness independently of lexical sign/scale/exponent. The complete original exponent grammar/counter/resource and facet checks still run; seeing only zero mantissa digits never permits an early successful return. The comparison witness is zero; original negative-zero or trailing-zero spelling remains retained and may have separately declared lexical/facet meaning.
4. NX04 for nonzero values remove trailing zeros from the remaining digits and compute exact normalized exponent = original exponent − original fraction digit count + removed trailing-zero count. Retain the nonzero sign, resulting digit string and exact signed exponent. Do not allocate 10^exponent, pad a scale-sized buffer or expand an exponent merely to compare values. Checked arithmetic/resource exhaustion refuses the complete correspondence.
5. NX05 mathematical equality holds exactly when both witnesses are zero, or both nonzero witnesses have equal sign, complete digit bytes and exact normalized exponent. Native numerical normalization cannot replace the original source token. A digest of digits, same printed prefix or matching rounded coefficient is not equality.
6. NX06 finalization retains original typed/facet admission plus source/native witness correspondence under original codec/custody. Native integer integrality, precision/scale/range and all source refinements remain independent complete checks; a matching mathematical witness cannot discharge them. A native producer claiming database enforcement must implement/qualify the original parsing/facet/correspondence procedure within its protected native boundary; host-only comparison remains engine evidence.

Normalization witnesses are internal ephemeral mathematical facts, not a new public numeric wire, portable key encoding, canonical source replacement or immutable codec definition. Independently qualify native number text grammar/settings/descriptor and source facets through CR01–CR06. This algorithm does not assume that all UMF numeric values are representable by the proposed native numeric slot. Unsupported values retain original source and explicit refusal; no float/string fallback is introduced.


[Eleven mathematical witnesses](bindings/numeric-correspondence-v0.1.vectors.json) independently specify normalized sign/digits/exponent for adjacent large values, retained trailing zeros, exponent shifts, negative zero and million-scale exponent notation. [Independent Python Decimal audit](../../04-build/evidence/design-audit/numeric-correspondence-vectors-audit.json) verifies all eleven witness values and seven mathematical-versus-lexical equality pairs without power-of-ten buffer expansion. Reproduce with `python3 docs/helix/04-build/evidence/design-audit/check-numeric-correspondence-vectors.py`. This validates finite authored mathematics only; it does not execute NX code, admit source grammar/facets, select a codec or prove native representability/resource enforcement. The million-exponent pair is deliberately a mathematical witness, not a PostgreSQL storage support claim; native-domain admission still precedes equality.


#### Numeric refusal precedence and facet preservation

NX witnesses intentionally discard lexical scale, exponent spelling and zero sign for mathematical equality. They cannot supply precision/scale/minimum/maximum or other facet evidence by themselves. Apply each original UMF facet under its selected semantic definition to the complete original admitted value/token facts; do not infer its meaning from a SQL numeric typmod, normalized digit count or Python Decimal's grammar. Retain the original mantissa fraction count and lexical exponent/sign facts where that definition requires them. Normalization never rewrites a facet or silently fills an unspecified one.

Admission order remains original context/profile availability → complete source/native grammar and bounded parsing → exact original facet/native representability checks → complete mathematical correspondence → final original custody. Refusal reporting follows the governing existing diagnostic/error producer and original violated path; these stages add no new error code or precedence override. A missing/partial native observation remains unavailable evidence, not a mathematical mismatch or a guessed zero. Once native work begins, resource/parser/correspondence failure follows original execution containment rather than being relabeled a clean pre-native refusal.

For zero, consume the whole token and validate its admitted exponent/domain/resource/facets before producing a zero witness. An oversized or malformed exponent must still refuse. For nonzero values, checked exponent arithmetic and full digit comparison must finish under the same whole-value/operation budget. Repeated normalization of the same stored value is real work; deduplication or equal hashes cannot reset charges. Temporary digit views/copies and normalization witnesses remain part of actual peak buffers, even though power-of-ten expansion is avoided.


NX's ephemeral zero/nonzero witness maps directly to ADR-006's existing zero/positive/negative coefficient/exponent tuple. The witness corpus's boolean negative flag is private oracle notation, not a proposed serialized tuple replacement. Existing ADR-006 fraction-oracle evidence and the newer Decimal witness evidence have separate scopes; neither adopts the separate compact decimal key proposal or supersedes UMF portable key ownership. ADR-006’s carrier/API direction is already accepted independently of these witnesses. Storage no-op equality still resolves through the selected original lexical-preservation profile under CONTRACT-004, not mathematical witness equality.

#### Bounded mathematical comparison for original numeric bounds

When the original selected facet explicitly means a mathematical inclusive/exclusive minimum or maximum, admit its original bound token and facet identity under the same source/definition/resource rules as the value. A SQL typmod, normalized witness or displayed constraint name does not select that meaning. The following internal comparison procedure may consume their fully admitted NX witnesses; it neither changes lexical precision/scale semantics nor registers a Weft/native comparator capability.

1.
