# Truss brand voice

Truss speaks to platform engineers evaluating connected data on PostgreSQL. Its promise is structural confidence: a model that can evolve, values whose meaning survives, and rules whose enforcement is visible. The positioning line is **Connected data. Grounded in PostgreSQL.** The name supplies a structural metaphor, not evidence of capability.

## Voice

Precise, composed and practical. Lead with the engineer's task; explain the mechanism in the next sentence. Use concrete nouns: property, edge, catalog, transaction, retained value. Define UMF as the schema metamodel and Weft as the query compiler. Use “you” for reader actions and “Truss” for product responsibility. Short headlines invite; body copy supplies qualifications. Sentence case throughout; capitalize Truss in prose and use lowercase in the wordmark.

## Claim discipline

Present tense describes repository facts and accepted design choices. Intended runtime behavior uses “designed to” or “planned.” Experiments name their engine/version and bounded evidence. Never imply production readiness, universal integrity, benchmark superiority or available hosted service. An enforcement report's database / engine / none categories remain distinct. Source signatures describe authorship and source integrity, not product correctness.

| Instead of | Write |
| --- | --- |
| Seamlessly unlock next-generation graph intelligence | Model connected data in your PostgreSQL database. |
| Guaranteed integrity at any scale | The design reports which rules the database, engine or neither enforces. |
| Get started in seconds | Inspect the design and reproduce a scoped experiment. |
| Schemaless flexibility | Publish schema revisions without per-type table migrations. |

## Message hierarchy

1. Keep connected data in PostgreSQL.
2. Evolve the catalog rather than one table per type.
3. Preserve exact values and unknown content; expose enforcement gaps.
4. Inspect the design, evidence and unfinished delivery gates.

## Audience and conversion

Primary: data platform engineers already using PostgreSQL. Secondary: schema/tool authors evaluating UMF and Weft integration. The conversion is informed evaluation: read the model, inspect evidence, then contribute through GitHub. No signup, invented customer quotes or unverified installation instructions.

## Review

Every page must explain a reader-relevant idea, link its governing source and distinguish intention from evidence. Audience demand and first external users remain unvalidated; this site does not claim adoption.
