# Original configuration custody and retention scenarios

These planned cases implement the [historical custody handoff](../02-design/contracts/installed-context-admission.proposal.md#historical-custody-and-cleanup-dependency-closure). Retain exact original/current configuration, binding, inventory and profile bytes, native source epoch/operation identity and complete expected report/receipt/feed state before execution. Original committed installation and protected producers are prerequisites; synthetic component profiles cannot qualify these cases.

| Case | Governing story plans | Independent expected observation and decisive failure |
| --- | --- | --- |
| CC-T01 historical report | STP-001 / STP-025 | Accept a real original revision, change current configuration, and resolve old context through its original private custody reference. Full original bytes and interpretation remain unchanged; wrong epoch/incarnation/profile/artifact refuses without using current state |
| CC-T02 no-op retry | STP-043 | Commit an all-no-op request with an actual durable receipt and no invented graph events. Eligible journal cleanup cannot remove required original configuration/context; exact retry returns the original ordered result under fresh current disclosure |
| CC-T03 unknown/adopted operation | STP-044 | Hold an adopted transaction and separately lose an original commit acknowledgment. Cleanup refuses while original settlement/recovery remains unresolved, even if no journal row is currently visible; original attempt is not resubmitted or replaced |
| CC-T04 feed correspondence | STP-041 | Two original operations share one compatible configuration, then a separate case has conflicting values under a claimed same generation. Verify complete prerequisite full-byte correspondence and per-operation custody; conflicting reuse refuses the complete manifest |
| CC-T05 revision-only transaction | STP-001 / STP-041 | Accept a revision without graph changes and verify complete original catalog/configuration prerequisites, committed membership and durable application. No fabricated object/edge supplies a per-record archive owner |
| CC-T06 archive completeness | STP-015 / STP-043 | Preserve graph history while deliberately omitting an independently required no-op receipt or operation configuration artifact from archive coverage. Cleanup refuses; upload/hash/per-record reconstruction success cannot discharge the missing owner |
| CC-T07 current protection race | STP-015 / STP-041 | Verify original external retrieval, then add a consumer/receipt/recovery protection before cleanup. Fresh exclusion/protection admission prevents removal; provider and database unknown outcomes remain distinct |
| CC-T08 disclosure | STP-025 / STP-041 | Deny a required private inventory/context fact through the selected security boundary. Historical lookup/feed publication returns unavailable without leaking protected raw bytes or trimming a purported complete artifact; a locator grants no read authority |
| CC-T09 enclosing resource profile | STP-001 / STP-026 | A native-valid capsule exceeds the selected complete report/archive encoding account. Refuse before publication or use an explicitly admitted compact-reference profile with verified original retrieval/lifetime; no silent truncation, limit enlargement or replacement of historical bytes |

Execute through packed public interfaces and qualified private services. Inspect original native storage, complete retained artifacts, provider settlement/retrieval and committed consumer state independently of returned success flags. Scope current 171-check live projection evidence separately; it supplies no CC-T01–09 historical/cleanup verdicts. Provider selection, operation-artifact archive coverage and exact accounts remain declared dependencies.
