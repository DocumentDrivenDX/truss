# Add-only acceptance scaling experiment — candidate 0.1

This procedure serves US-006-AC3 under TD-006/STP-006 and CONTRACT-003.
It is an execution candidate, not a performance receipt or adopted release
threshold. Exact environment, corpus, timer and native resources remain to be
registered. It preserves full acceptance semantics and the 45-story scope.

## Independently authored matched fixture

The baseline has ten existing object types Type000 through Type009. The large
arm preserves those definitions and adds Type010 through Type999. Each existing
type has one required string field label. All types have zero objects; both arms
have zero edges, retained values and pending index jobs. Preserve the same model,
ownership, grants and source-extension meaning for the shared definitions. The
additional990 definitions and their unavoidable catalog bytes are the intended
difference; retain exact source bytes and complete independent inventory for
both arms. This experiment does not characterize populated transforms or general
validation cost.

Each new candidate adds Shipment with required string field label and an optional
relationship to the unchanged Type000. Include no authored physical index request,
key backfill or value transform. Independently declare the complete expected
accepted catalog/report/head/history outcome and unchanged physical inventory
before execution. Resolve actual native identities through original fixture
observations; do not guess IDs or force both arms to reuse one installation epoch.
Candidate bytes differ only where the selected source/definition identity and
revision procedure requires correspondence to their respective original arms.

## Measure a fresh operation every time

Measure from entry to the installed public acceptance operation through complete
report admission and confirmed engine-owned commit/result return. Include actual
original input admission, UMF interpretation, catalog preparation/validation,
head transition, required history/report/receipt work, transport and final
publication. No writer or catalog-head competitor runs in this experiment;
retain observed waits rather than subtracting unfavorable processing time.
Caller-owned provisional acceptance needs a separately registered experiment
and cannot replace confirmed engine-owned acceptance here.

Each warm-up and measured call uses its own freshly prepared equivalent original
source state. Preparation/installation and independently verified reset occur
outside the measured interval and must complete before invocation. A previously
accepted revision, exact-repeat/no-op result or cumulative sequence of additions
cannot stand in for a new add-only acceptance. Do not restore a live source or
copy original attempt/recovery authority: each fixture obtains its own admitted
installation/context. Declare and retain cache/statistics preparation consistently
for both arms; restored-cache differences create a new registration.

## Sampling and candidate comparison

Use three blocks, each with30 unmeasured paired warm-ups and1000 measured pairs.
Alternate10/1000 arm order on odd/even pairs. Retain every actual outcome and raw
exact monotonic nanosecond duration. Independent observers compare the complete
accepted state, report and required history, and unchanged native table/index
inventory after every sample. Refusal, unknown commit, incomplete observation or
changed expected result invalidates the block; no automatic retry, replacement
sample or deletion of an outlier can turn it into a pass.

For each arm/block use the950th sorted duration as nearest-rank p95. The proposed
engineering interpretation of comparable time is large-arm p95 <=2 * baseline
p95, using exact integer arithmetic with a positive denominator above qualified
timer resolution. All three blocks must pass. This ratio is a candidate pending
release-profile selection, not an inferred numerical promise from the story.
Report medians, maxima, full raw pairs, payload sizes and native stage/lock work
as supporting evidence without substituting a favorable statistic. Include full
1000-type input and complete report work; measuring just catalog INSERTs or
subtracting parsing/validation cannot qualify acceptance scaling.

Seal original runtime/build/driver, installation/model/UMF/security/value/resource
profiles, server/session/hardware settings, exact source/candidate/expectation
artifacts, native observer and timer/caching procedures before sampling. Missing
instrumentation is unavailable, not zero cost. Independently test deliberate
wrong-result, repeat-acceptance, zero-denominator, missing-sample and failing-ratio
controls before trusting the experiment runner. All native samples and runner
controls are not_run; existing page/planning benchmarks cannot substitute them.
