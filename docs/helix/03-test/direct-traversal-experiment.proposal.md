# Direct traversal performance experiment — candidate 0.1

Authority: US-023, TD-023, STP-023 and TP-001. This selects engineering sampling
and comparison rules, not the pending output/cycle interpretation or a supported
native profile. Every execution case remains `not_run`.

## Registration and equivalence

Register one, two and three hops separately, with independent direction, degree
and filter strata. Every required stratum must pass. Retain complete graph bytes,
queries and independently authored expected typed identities, values and order.
Register limits sufficient for complete results; a limited/refused traversal
cannot count as a fast complete result. Stage creation, expansion, decoding and
all pages needed for the complete result belong to the measured operation.
Page-one latency and precomputed stage/result-cache lookup are separate metrics.

Build the hand-designed PostgreSQL baseline independently from Truss templates.
Freeze schema, actual statements, parameters, indexes and decoding. Both arms
must implement the selected identity, direction, path-cycle, terminal uniqueness,
filter and completeness meanings under equivalent data/snapshot and actor/policy.
Obtain the security owner's exact lawful baseline profile; do not silently disable
mandatory checks. Required native/control/account and publication/cleanup work
stays inside timing. Weft bags and host-rewritten SQL are not this baseline.

The packet must specify graph sizes/inventory, starting identities, authored hops
and inverses, selectivity, complete expected results/expanded-work counts, limits,
semantic interpretation and baseline implementation. Required graph families
remain chains, diamonds, cycles/self-loops, isolated roots and high-degree
expansion, with filtered and unfiltered cases. A tree where interpretations happen
to agree cannot qualify the whole profile. Concrete corpus and native/baseline
implementation remain registration outputs; no installed fixture is claimed.

## Public-call latency — AC1/AC2

For every required stratum, run three blocks, each with 30 unmeasured warm-up
pairs and 1,000 measured pairs. Alternate Truss/baseline and baseline/Truss order.
Use one pinned monotonic clock and exact integer nanoseconds from API entry
through complete validated assembly and required operation cleanup. Pin host
transaction mode; adopted reads do not commit outer work to end timing. Freeze
preparation/cache, hardware/runtime, concurrency, server settings and statistics.
Compilation and fixture restoration are excluded only identically and explicitly;
production validation remains measured.

Use each arm/block's 950th sorted duration as nearest-rank p95. Require Truss
p95 <= 2 * baseline p95 in all three original blocks for every stratum, using
exact arithmetic. Baseline p95 must exceed qualified clock resolution. Retain
median, maximum and every raw paired sample in order. Wrong membership/value/
order, missing samples, errors, timeout, exhaustion or configuration drift
invalidate the block. No discarded outliers, replacement blocks or retry to
green. Invalid denominators make ratios unavailable.

## Metadata planning — AC3

Keep the same selected one-hop graph, data, relationship count, query/result and
native index obligations in isolated 10-type and 1,000-type catalogs. Add 990
unused object types without data. Record namespace/revision/statement differences;
retirement in one growing catalog cannot recreate an independent smaller arm.
This measures **type count**, distinct from US-011's relationship-count experiment.

Use the actual production statement packet and server-reported Planning Time
instrumentation from the [relationship-planning procedure](relationship-planning-experiment.proposal.md#measurement-and-registration),
including complete nested planning or unavailable scope. Reuse its three blocks,
30 warm-up/1,000 measured pairs, nearest-rank p95 and exact 2× rule for 1,000
versus 10 types. Retain original EXPLAIN bytes, lossless timing tokens and pinned
uncached/custom-plan treatment. Planning cannot satisfy public-call AC1/AC2.
No handwritten substitute is allowed for an uninstrumentable production route.

## Assessment and open exits

Independently exercise one-unit ratio violation, missing sample, zero/resolution-
limited baseline, wrong result, changed profile and cycle-rule mismatch. Require
failure/unavailability despite favorable timings. Bind the receipt to the original
packet, source/build/profile/native pins, raw samples and reviewed complete
correctness facts. The private relationship-planning ratio helper assesses one
block's integer arithmetic only, not fixture equivalence, timing provenance or
three-block/native qualification. Corpus, baseline, runner and actual native
evidence remain open; this procedure establishes no support claim.
