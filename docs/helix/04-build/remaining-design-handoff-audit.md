## Next integrated deliverable

Produce a single reviewable authored composition for the reference original Account/Item model: original source and four value/presence/codec/home definitions, complete protected operation/caller/role/dependency interfaces, driver/account observations, and compiler-owner mapping requirements. Keep native identities/evidence explicitly future-bound instead of manufacturing them to fill nulls. Preserve the complete wider product requirements and unsupported-profile outcomes; the reference model is an integration checkpoint, not a replacement product scope.

Only after that composition is internally consistent can implementation generate actual bodies/registrations, inventory them and run the existing independent qualification plans. Draft source bodies/prototypes may help resolve interface ambiguity, but their inclusion is the outstanding scope clarification; installation and production execution remain separate. Repeating SQL round trips, adding source hashes or widening fixture counts alone cannot close the integration design gap.

The recent numeric, equality, participation, actor and network host handoffs are concrete component advances. They do not establish a complete native composition, consumer reconciliation or Weft explicit-null interpretation. The next work should prioritize these missing interfaces and original inputs over further standalone consistency receipts.
