# Python group contract slice

The public `truss.contracts` and `truss.groups` modules describe draft grouped-operation inputs and results. `GroupCapability` is a synchronous Protocol; this slice provides no callable mutation provider, adoption factory or ReferenceAssembly. The existing private executor remains private. C01 remains open for the other capability contracts and C02 remains open for the assembly.

Python uses snake_case members and immutable tuples for TypeScript readonly arrays. Nonempty operations, journal events and semantic results are encoded in typing and checked at construction. Replay metadata remains nested under `replay`. Optional members use `ABSENT`, distinct from a present null value and an empty string. Exact integer, decimal, timestamp, binary and opaque source spelling remains text; value-domain interpretation is owned by the admitted UMF profile. Profile and artifact carriers validate shape only: they do not verify digests, canonical encoding, profile registration or native evidence.

Consumers first inspect the outer `Outcome`: `Error` preserves its complete `ExecutionFailure`, including retry scope and SQL state. It must not become a successful result, invalid semantic input or an automatic retry. `Ok` contains a separate application result: `success` carries the complete ordered semantic result; `failed` distinguishes group operation failure, invalid input and request conflict; `unavailable` preserves its reason. Operation results retain unchanged entries and distinguish created, changed and deleted identities. An in-transaction applied result is pending. Same-transaction replay is pending; committed-receipt replay carries committed durability and its own evidence basis. Constructing these values proves neither execution nor commit.

A request-free call excludes replay, request conflict and receipt-specific unavailable reasons both in its static return type and in `validate_request_result`. A request identity describes authorized scope and request key; this slice does not implement namespace admission, lookup, durable receipt persistence or idempotent retry. Missing or expired receipt evidence must not authorize re-execution.

Execution failure code/retry-scope correlation remains **runtime-only** validation in the existing `ExecutionFailure` dataclass. Static annotations enumerate possible codes and scopes independently; this slice does not claim equivalent TypeScript negative typing for contradictory scope combinations. The tests explicitly reject those combinations at runtime. The current nominal transaction handle describes caller ownership only and exposes readonly metadata. Constructing an unregistered handle grants no authority; only the private executor's original issuer and exact registered instance can admit it.

`GroupCapabilityResult`, readiness admission, factory registration and safe construction diagnostics remain deferred with the assembly. Installation and actual graph operations require the security/native semantic prerequisites in the integration plan.
