# Truss v0.0.30 — unreleased

The native66 candidate accepts standalone singular scalar Fields as declarations
without inventing storage properties. This supports a consumer model whose
transform-input Field belongs to no Record. Original document bytes, assertion
inventory and the supplied document revision remain intact. UMF0.8 acceptance
selects the explicit Truss support0.17 profile; older profiles keep their original
ownership rules. Standalone containers and unknown selected shapes still refuse.

The unchanged consumer model passes public catalog acceptance, creation of its
five Records, read-only object/source/business-Key reads, and actual native query
binding export on PostgreSQL18.6 with psycopg3.3.6. Its original opaque token seed
is preserved; acceptance does not install a token implementation or security policy.

Native65 multi-entity transition storage is included. A populated65→66 upgrade
preserves original transitions and receipt replay, followed by successful writes.
Direct object/key/page results expose the rootless ownership guaranteed by their
current read profile through `ScalarObject.ownership`. Owned-object creation,
reparenting, reads and cascades remain unfinished.

The local candidate wheel also completes that public workflow when installed
separately from the source package. It is an unpublished build, not a release
asset. Astra Ultra reviewed these changes. Final native manifest SHA256:
`99ae7218e0e3e68e0a3682e43949089185d967eb21bbf31deb0b8f8f6fc2de9a`.
Layout1.0 is unchanged. The matching supported Weft cohort and published wheels
are pending. The existing native63 upgrade/query gate reaches its query assertion
and refuses with the old compiler; it has not passed for this candidate. No release
tag or wheel publication is claimed here.
