# Truss v0.0.38

Python applications can deploy Truss without Bun, Node or an external JavaScript
process. The package pins `mini-racer==0.14.1` / V8 14.4.258.23 and executes the
original packaged UMF producers inside an isolated context. Original source
bytes, owner manifests, exact receipts, unknown content and key encodings are
retained. Packaged modules and polyfills carry a separate pinned delivery
manifest and third-party licenses. No host filesystem, environment, network or
process interface is exposed to these modules.

This is an update of the published 0.0.37 functionality. Native SQL remains
`truss-catalog-runtime/0.70-candidate`, byte for byte. The supported release tuple
is Python3.11, PostgreSQL18.6 (`pgserver-pg18==18.6.1`), psycopg3.3.6 and released
Weft0.4.41; ordinary queries retain backend0.4.40 / target0.4 / interface0.2.6.
The stable release gates run against the installed wheel on Linux x64 and macOS
ARM64 before publication. This release does not expose the unreleased owned-graph
features on main, whose original capacity gates remain unresolved.

The `bun_executable` keyword remains accepted for compatibility and is ignored.
Preparation provenance now identifies the embedded runtime. Original build-time
Bun pins remain source provenance. Current-policy queries retain one held
context, complete original frames, request/source correlation, one shared
deadline and permanent refusal fencing. Existing protected-query registrations
require explicit re-enrollment when changing the exact compiler/runtime cohort;
ordinary unprotected native0.70 installations require no SQL migration for this
packaging update. Historical predecessor-wheel upgrade tests keep their original
Bun oracle as test-only tooling.

A native UMF library is the selected follow-up to remove V8. It is not implemented
by this release. UMF retains metadata and policy ownership; Weft retains SQL
compilation ownership.
