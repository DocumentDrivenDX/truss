# Truss v0.0.39

This tranche adds ordinary owned graphs, atomic owned imports and owned-object
catalog evolution to the public Python reference assembly. It targets PostgreSQL
18.6 with DocumentDrivenDX `pgserver-pg18==18.6.1` and psycopg 3.3.6. The package is `0.0.39`, native `0.71-candidate`. It targets Linux x64 and
macOS ARM64. This release is for Python embedders and is distributed through
GitHub Release wheels, source archives, checksums and exact dependency pins.

Independent rootless creates, stored-object updates and stored-endpoint edges now
write objects, keys, journals and transition evidence in batches. The 1,000-create
control verifies one object INSERT rather than 1,000 individual object INSERTs.
Final validation avoids history-dependent quadratic joins. Native key metadata
is compiled once per phase, and private indexed lookup functions reuse plans
while preserving caller settings. Original authorization, key reservations,
semantic validation, commit guards, ordering and rollback remain enforced.

Catalog registration uses a compact original validation summary rather than
repeating full evidence. Original pizza, Northwind and catalog models have
native registration and representative-load evidence; this does not qualify
all operations on every ontology.

[The tested source campaign](https://github.com/DocumentDrivenDX/truss/actions/runs/39084247653)
passed both complete installed-wheel native jobs, original 1,024-operation
capacity controls, analyzed-history custom/generic caller-plan controls and the
full 1,000-object/1,000-edge public workload. The tag workflow repeats these gates
for the final versioned package before publication. Statement 10s / operation 30s
budgets are unchanged. Hosted 1,000-create calls took 2.05s on Linux and 3.00s on
macOS, excluding commits; five 1,000-object update calls completed in 3.52–3.94s
and 6.48–7.80s respectively. These are one-campaign observations, not p95 or
broader stress qualification. [Full evidence](../../03-test/performance/results/2026-10-17-final-hosted-qualification.json)
retains commit timings and exact scope.

Python deployment requires no Bun, Node, or external JavaScript process. The
wheel pins `mini-racer==0.14.1` and executes the preserved UMF producer modules in
an isolated V8 context. Exact packaged source bytes and owner receipts remain
retained; compiled delivery assets carry a separate pinned manifest. No host
filesystem, network, environment or process API is exposed to the owner modules.
Stateful query/disclosure invocations retain one context, shared deadline,
original frame correlation and permanent failure fencing. The legacy
`bun_executable` keyword remains accepted and is ignored. Bun remains build-time
and historical-oracle tooling. Existing registrations select exact consumer
cohorts and require explicit re-enrollment when the compiler/runtime selection
changes. A native UMF library is the selected follow-up to remove V8; this release
does not claim that implementation exists.

Create aggregate roots, owned children and directed edges in one group. Reparenting
requires an explicit `UpdateObject.ownership_change`; changing an owned edge's
endpoints does not silently reparent its target. Descendant roots and versions
change atomically. Cascades remove the owned subtree and its owned edges;
independent incident edges must be explicitly removed in the group.

Identity, business-key, page, relationship, traversal and retained-history reads
preserve ownership and require the corresponding current root readers. Historical
images preserve their original roots after reparenting or deletion. `LogicalObject`
reports ownership; the existing `ScalarObject` remains the rootless carrier.
Dry-run uses real execution followed by caller rollback. Original committed
receipts replay after cascade deletion.

Modern owned groups admit up to 1,024 operations; legacy rootless groups retain 128.
The original capacity workflow creates 1,024 objects, commits, performs 1,024 changed
updates, commits, replays the original receipt and reads every result back in order.
It also checks refusal at 1,025 and whole-group rollback on a final-operation fault.
The existing 10-second statement and 30-second operation deadlines are unchanged.

Explicit owned imports create roots, children and edges through earlier primary-key
references, retaining indexed source provenance in one atomic transaction. Caller
settlement stays caller-owned; the batch runner commits the complete explicit
owned aggregate. Existing per-record imports retain their prior semantics.

Alternate-key backfill and retained-value rebinding now support existing owned
objects. Registration, report retry and commit require readers for the original
aggregate roots. Backfill preserves object images, versions and mutation history.
Rebinding preserves before/after historical interpretation, including an independently
affected root definition, and can compose with alternate-key backfill.

Ordinary compiled queries use published `weft-sql==0.4.41`, backend 0.4.41,
binding 0.5, compile/IR/backend 0.2.7 and the exact logical query ABI 1.1. The query
extra selects that published compiler. The typed-SDK extra remains deferred until
a matching immutable public UMF artifact and fresh consumer-install workflow pass.
Experimental typed cursor streams now refuse unproved completion at `max_rows`:
after releasing the bounded prefix and completing native cleanup, they raise
`QueryStreamRefused` with `limits` / `stream_row_limit`. A short final fetch
proves exhaustion and ends normally. This uses existing Truss carriers and
does not enable the deferred public SDK dependency. The [scoped correction evidence](../evidence/typed-sdk-stream-limits-20261017/README.md) records five adapter tests and 16 basic native checks; generated-query catalog
and large-stream qualification remain separate.

SQL uses stable UMF IDs when
names are absent and refuses ambiguous names. Signed 64-bit integers, decimal(18,4), decimal(18,2)
and decimal(12,2) queries preserve exact values. Canonical Gregorian Date projection,
equality and pages retain `TextValue(kind="date")`, including absent/null distinctions.
Date equality accepts literals, fields and exact parameters for years 0001–9999.
Earlier captured ABI bindings require recapture; they are not silently rewritten.

The original 14 non-temporal typed-SDK checks pass with published Weft 0.4.40 and
a pinned local UMF wheel. They do not establish published UMF dependency availability.
This evidence does not enable typed-engine Date outputs/parameters, Date ordering/keys or
other generic-decimal query domains. The separately activated current-policy
profile retains its existing scope; this release does not enable protected owned
facts, aggregates, actions or UMF projection V2. The browser demo keeps its own pins.

Catalog preparation uses one document-validation summary. Report 0.5 retains original
source, diagnostics and original-report retries. Core UMF 0.7/0.8 are admitted under
the selected support profile; all 21 core-UMF ontology documents in the UMF 0.8 domain
packs at `cbb6fb8718aad59fd2061b62d12976387570db2f` have native registration evidence.
The 256 TableSpec entries are a different input format. This does not establish
support for every valid UMF construct.

The native operation-storage table is generated from its UMF model. Published
native 68/SDK 0.0.35 and native 70/SDK 0.0.37 upgrade routes retain original rows, keys,
receipts and provenance. Installation and upgrades remain explicit host operations.
The public `owned_objects_workflow.py` example uses only public Python APIs.

[Local functional and performance observations](../../03-test/performance/README.md)
include the unmodified consumer models and the original 1,000-node/1,000-edge workload.
They do not establish provisional latency targets or broader scale qualification.
The release workflow independently checks the final versioned installed wheel
on both platforms before publishing package assets.

Record-valued cells, cyclic value definitions, history offload/cleanup, additional
SQL domains and managed Aurora/Lakebase qualification remain unfinished. No managed
database deployment environment has been supplied.

## Upgrade and rollback

Install `truss-toolkit[local,native,query]==0.0.39` using the release wheel links
in the [Python installation guide](../../../../packages/python/README.md).
Existing native0.70 installations (SDK0.0.37/0.0.38) require an explicit native
upgrade: quiesce consumers, back up the database, and invoke
`upgrade_in_transaction(tx)` as the trusted installer, then commit and check
status. The equivalent local command is
`truss-local-postgres --data-dir PATH --upgrade --probe`. Opening a connection or
installing a Python wheel does not migrate a database. Populated native68 and
native70 upgrade workflows preserve original data, keys and receipts.

Captured query bindings require recapture for the changed ABI; protected-query
registrations require explicit re-enrollment for the exact compiler/runtime
cohort. Downgrades are unsupported. To roll back an upgraded database, restore
the pre-upgrade backup with its matching previous package. Keep an existing
installation and package together when holding a rollout. Report issues through
[the repository issue tracker](https://github.com/DocumentDrivenDX/truss/issues)
with the exact release pins and failing public operation.
