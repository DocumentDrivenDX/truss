# Truss v0.0.48

## Release scope

Candidate for Python embedders and operators; publication remains gated by the
[follow-up plan](../hohfeld-followup-plan-20261021.md) and
[managed grants plan](../managed-platform-grants-plan.md). Python3.11+, PostgreSQL18.6,
psycopg3.3.6, mini-racer0.14.1, UMF0.10 and Weft0.4.51 form the selected tuple.
Native0.74-candidate has manifest SHA-256
`35fd797b5cf48dd888c68e53b9e599df20cffe00f8f3d33e1563820ea808d59f`.
Release assets and this guide communicate the changes to embedders/operators.

## Highlights and changes

- Finite person entrypoints return typed nonmembership refusals while actual
  damaged EXECUTE grants remain native execution errors. Statement-stable data
  sources retain their original snapshot with independently current authorization.
- Frozen complete group requests support observer-only recovery. Missing,
  conflicting or unauthorized observations never execute the group again.
- Empty Records allow the paired core/DDD required-field addition; populated
  Records refuse it, including retained matching values. Existing qualified
  core-only retained-value rebinds continue to work.
- Weft-owned descriptors, explicit ordered entity facts and relationship
  projections, typed resolver diagnostics, selected indexed predicates and key
  pages use query ABI1.2. Other domains retain bounded complete fallback reads.
- Completion and group dry-run force only Truss's deferred constraints and
  publish observation carriers after host-owned rollback. They preserve prior
  caller work and produce no durable receipt or committed created identity.
- Authorized cross-module audit discovery, whole mutation metadata up to4,096
  events within its byte bound, and optional reader-authorized archived key/version
  projections. Relationship-only load discovery/details now retain exact owners
  and actor names; old incomplete headers remain unavailable.
- Deduplicated import owner inventories reduce measured residual import work;
  all original inputs still receive authorization checks. Performance evidence
  is workload-specific and establishes no general latency/p95 target.
- Fresh installation accepts an explicit bounded tuple of existing tolerated
  platform-role names. Empty policy remains strict. Selected grants and grant
  options remain in place; immutable installation evidence records their initial
  native name/OID and ACL observations. Later administration verifies those role
  identities, while ordinary ACL, ownership and effective-access checks remain.
  A contained `third_party_grant` refusal identifies an unlisted role and safe
  object-class/phase context; the local CLI emits the safe refusal as JSON and
  exits with status 1. Separately protected activation refuses nonempty
  policy with `unsupported_profile` before effects.
- The independent corpus archive and installed runner are release assets.

## Required actions and migration

Only the latest runtime is supported. Admitted previous databases migrate
forward without a release-age cutoff. Previous application releases do not
remain supported. This release retains the original0.0.44, shared0.0.45/46 and
0.0.47 migration sources and all immutable prior recipe/receipt evidence.

Quiesce writers and back up both database and host recovery registry. Follow
[the migration guide](../../../../packages/python/README.md#runtime-migrations--v0048):
inspect status, prepare and retain the reference, apply that reference, reconcile
uncertain settlement, and verify before resuming latest application work.
Startup never migrates. One complete route publishes one final receipt; prior
receipts remain unchanged. Install the matching Weft0.4.51 query dependency.

Existing admitted strict installations receive the empty managed-grants policy
through the explicit forward recipe. Migration does not opt them into platform
trust. Only fresh installation selects tolerated identities; renamed or recreated
roles refuse until explicit administrative reconciliation. The initial ACL
observations remain historical provenance, allowing later grants to selected
identities within the documented trusted platform boundary. Private defaults and
all ordinary privileges retain exact checks.

Exact text ACL inventories now distinguish sibling overloads. Separately pinned
supplements strengthen old-profile admission without rewriting published source
profiles. Native drift refuses before effects. Logical restores require the
original backup-metadata companion for PostgreSQL's omitted row-type ACLs.

## Hold and recovery

Hold on drift, failed verification or uncertain settlement. Reconcile the same
original attempt; do not repeat effects with a new request. Pre-commit failure
rolls back; committed changes require a forward fix or the qualified backup
restore/remigration workflow. Installing an old package is not database rollback.
