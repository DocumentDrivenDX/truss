# Truss v0.0.35

Fixes the release checks and private metadata-source inventory for native68.
The v0.0.34 workflow refused publication because an upgrade test still expected
native67. Current-target assertions now follow the packaged runtime, and the
metadata-source verifier requires all 164 original native68 routines. Its
body, signature, owner and ACL checks remain intact. The failed v0.0.34 tag is
unchanged.

Unifies genuine object creation with the common mutation transition ledger.
A create followed by update or delete retains its original creation journal,
key reservations, ordered results and idempotent receipt. Populated native67
installations upgrade without rewriting original transition rows or receipts.
The physical constraint change is generated from the saved UMF storage model.

Pairs native68 with published Weft0.4.34 / backend0.4.37. The release selects
explicit public macOS ARM64 and Linux x64 ABI2 compiler cohorts; earlier
registrations keep their original whole source selection. It does not silently
migrate a development or older consumer registration.

The existing public catalog, mutation, key/direct read, query, import, history,
feed and receipt interfaces retain their scope. The explicitly activated
current-policy query remains read-only, rootless, required String/signed64 with
original UMF579675bd policy/disclosure evaluation and Weft ABI2. No ABI3/4 or
aggregate-security capability is enabled by the newer wheel.

The release workflow checks the installed wheels on PostgreSQL18.6/macOS ARM64
and Linux x64. Managed databases, owned-object mutation/lifecycle and the broader
protected engine remain unfinished. Native69 ownership work is excluded from
this release.
