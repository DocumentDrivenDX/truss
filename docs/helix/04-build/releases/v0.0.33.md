# Truss v0.0.33

Adds the public `query_current_in_transaction` interface with original UMF
policy/disclosure evaluation, original Weft query preparation and private
PostgreSQL staging. Exact signed64 predicates can select masked String output
without disclosing denied rows. Empty and entirely denied populations return
empty rows when genuine query routes establish a single projection domain.

The trusted installer must finish bootstrap and Subject enrollment, quiesce
ordinary sessions/new connections, activate protection explicitly and commit.
Activation removes legacy data routine grants and refuses pre-existing external
privileged definers, exposed views/rules and routine attachments. The activating
administrator is the sole exempt LOGIN; other CONNECT-capable privileged roles
refuse. Supported configuration/bootstrap paths cannot silently regrant access.

This initial activated profile is read-only through the current-policy query:
rootless, required String and signed64 values on local PostgreSQL18.6, Linux x64
and macOS ARM. Projection-only empty domains, nullable/structured output,
aggregates, protected mutations/imports/direct reads/history/feed, owned-object
lifecycle and managed databases remain unfinished. The host supplies a dedicated
private executor transaction and maintains administrative DDL quiescence.
Unactivated public APIs retain their previous behavior.

Requires matching Weft0.4.33 wheels. The release workflow checks installed basic
policy-query/activation workflows on both native platforms alongside existing
adopter workflows. The native67 layout and stored key bytes are unchanged.
This release does not claim complete security-suite or all-interface coverage.
