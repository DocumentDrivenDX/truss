# Frontier review: participating routine DDL and original epoch fences

Disposition: a useful next administrative feasibility component, but the existing issuer cannot be silently reused as a truthful automatic routine-change publisher. Resolve the transition meaning, bounded evidence carrier and participating-writer serialization before implementation. No source edits or native execution were performed for this review.

Existing evidence is narrower. UMF `tools/security/pg-policy-activation.py:350–386` and `docs/helix/04-build/evidence/security/pg-policy-activation.json` qualify a PostgreSQL17.9 CREATE FUNCTION start hook using a transaction advisory lock. A later CREATE OR REPLACE writer waits through installer commit and then rolls back. Its mode is O, not ALWAYS. It neither tests a completed but uncommitted DDL writer nor advances epoch on committed DDL. Current Truss has the explicit issuer and fenced reader, not an automatic start/end producer.

Concrete design constraints:

1. **Reconcile actual transition meaning.** `source-epoch-issue.sql` labels every successor `restore`, and the owner storage model CHECK admits only initial/restore. Routine creation, modification and removal are not deployment restores. Use an explicitly governed candidate transition meaning and corresponding owner-source layout, or keep any unchanged-issuer experiment explicitly synthetic and unsuitable for authentic transition interpretation. Do not change only an emitted label or infer authority from the epoch token.
2. **Do not fit the full census by truncation or digest substitution.** The existing census permits 16 MiB and the retained baseline is about 11 MiB; original epoch evidence admits at most 1 MiB. The lifecycle proposal requires original evidence/full-byte custody, not digest-only authority. A bounded evidence descriptor can explicitly identify a separately retained original census under a new candidate protocol, with exact digest/length/profile/affinity correspondence, but it does not automatically satisfy the existing full-evidence requirement. Census NULL, capacity exhaustion or retention failure must abort the DDL transaction.
3. **Serialize before taking the evidence snapshot.** Both epoch ROW EXCLUSIVE locks exclude SHARE readers but are mutually compatible between writers. Taking a census before the existing issuer's later marker/pointer locks can associate stale evidence with a newer serialized predecessor. Acquire current then registry modes, then the original marker and pointer locks in consistent order before relevant DDL, or independently prove an equally strong serialized recollection rule. Qualify timeout/NOWAIT behavior; the existing marker/pointer FOR UPDATE can wait. Test two simultaneous writers, not only reader/writer conflicts.
4. **Refuse the backend's own reader before effects.** Start must perform the actual granted ShareLock check on either epoch table and raise55000 before executing DDL. Acquiring ROW EXCLUSIVE does not conflict with locks held by the same backend. An end-only issuer refusal rolls transactional DDL back but cannot substantiate a before-effect admission claim. Preserve the current→registry→marker→pointer order and exact database/PID identity.
5. **Declare the command subset conservatively.** At start, TAG is the supported native filter; do not recover qualified targets by parsing current_query. Blanket gating of the selected tag family is honest and may affect unrelated routines. CREATE FUNCTION alone misses ALTER/DROP FUNCTION, PROCEDURE/ROUTINE aliases, aggregate semantics, local grants and indirect schema/type/extension cascade changes. Either exercise a closed selected subset and explicitly exclude other writers, or refuse unsupported routes under a separately enforced profile. Do not call a tag-filtered experiment complete pg_proc writer coverage.
6. **Keep start/end and nested behavior closed.** Pin both hook bodies, definitions, enabled ALWAYS modes, tags, owners and the surrounding event-trigger inventory. Use the same supported event set. The handlers themselves should not issue DDL. Nested DDL and additional hooks need an explicit admitted/refused rule; do not bypass using a caller-settable GUC. End events are before commit, failed DDL skips end, and a failing end handler rolls back the statement. Multiple hooks run in name order: evidence collected before another end hook can be stale unless subsequent relevant changes also participate. Start/end erasure controls must be separate.
7. **Preserve invoker and bootstrap boundaries.** The original issuer rejects implicit SECURITY DEFINER elevation; changing the hook to definer to obtain epoch privileges is a new authority design, not a plumbing fix. This spike can remain an explicit administrative invoker fixture. Do not grant ordinary direct epoch DML. Install dependencies and both enabled hook definitions in an excluded bootstrap transaction, capture that final installed state, and seed the provisional epoch before exposure. Missing marker/helper/table must refuse after bootstrap, not activate a permanent skip path. A transaction predating hook installation is not retrospectively made a participating writer.
8. **Do not infer a complete held source cut.** ALWAYS addresses replication firing mode; it does not prevent privileged disable/drop, direct catalog modification or same-process tampering. Event-trigger DDL itself and shared objects are outside this event mechanism. Source/configuration/role/authorization-fact writers, nontransactional effects and nonlocal domains remain separate. A fresh READ COMMITTED census after reader acquisition is needed, but endpoint equality and catalog metadata do not prove current callable/plan equivalence. The existing Python epoch acquisition conservatively invalidates on the next ordinary native call, so this administrative sequence is not yet an admitted protected dispatcher.

Decisive native controls should include: completed-uncommitted DDL with both granted epoch modes independently read back and reader refusal until commit/abort; fresh reader census/epoch after commit and unchanged lineage after abort; reader-first external refusal; own-reader start55000 before a nontransactional sentinel; committed A→B→A with equal final body but distinct successor lineage; two simultaneous writers; end-hook failure and savepoint rollback/RELEASE ancestry; replica-mode ALWAYS behavior; exact installed pair metadata; isolated missing-start and missing-end mutants. Unsupported/privileged routes should be demonstrated or explicitly excluded, not assumed covered. Restrict initial selected commands to transactionally understood routine DDL; do not generalize to concurrent-index or other special transaction commands.

This review is design guidance, not execution evidence or source/native refinement.

Updated selected direction: the parent has narrowed the implementation to a barrier-only adjunct, with no end hook or epoch issuance. Its six tags are CREATE/ALTER/DROP FUNCTION and PROCEDURE. An invoker start hook first refuses an actual own reader SHARE, then takes current/registry ROW EXCLUSIVE NOWAIT and marker FOR UPDATE NOWAIT. This is a coherent material prerequisite and avoids falsely labelling routine edits as restores or claiming full-census evidence fits the issuer. No scoped blocker to this selected administrative implementation was identified. The earlier end-publication constraints above remain requirements for a future publisher, not missing work in the narrowed adjunct.

Successful selected DDL intentionally leaves the epoch unchanged. An explicit positive must show unchanged epoch together with changed routine body/fresh census, so epoch identity cannot be mistaken for source equality. Reader source observation must be a fresh READ COMMITTED collection/comparison after fenced acquisition and while the cut remains held. Pending commit/abort, concurrent writer serialization, same-reader early refusal, isolated hook/predicate erasures, exact ALWAYS/six-tag metadata, ordinary privilege refusal and definer-context refusal remain the discriminating controls. The selected exclusions for aliases, aggregates, cascades, grants, shared objects, event-trigger administration and all other source writers remain essential. No additional held-source scope or protected admission should be issued by this adjunct alone.
