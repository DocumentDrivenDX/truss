# Independent installation observer execution handoff

This packet implements the read-only inspection/verification path governed by
CONTRACT-008/012, the existing layout-migration binding and the migration
inspection walkthrough. It complements the Python installation handoff; it
introduces no new public result variant, ledger, lock or authority interface.

## Original inputs and observation order

1. Resolve the registered inspection procedure/resource profiles and original
   independently expected complete release membership. Admit actual observer,
   connection, current authority, configuration and coherent cut through the
   owner's closed protocol. Missing services refuse before collection; a supplied
   profile name or expected digest cannot grant observation authority.
2. Reserve the selected complete receive/allocation/work/deadline allowance before
   collection. Retain original result descriptors/completions/cells for every
   required inventory surface. Do not truncate, drop duplicates or select only
   expected names: unexpected managed members require observation too.
3. Collect full managed objects/dependencies, all native routines/call paths,
   triggers/partitions, owners/effective rights/policies and complete initializer,
   configuration/epoch/marker/archive contents under the same admitted cut.
   Dynamic dependency meaning requires declared inventory and behavior, not
   pg_depend alone. Observe full original role/identity/bytes of each archive row.
4. Compare both inventory directions against independently registered originals.
   Counts, names, hashes, marker/version equality and current package contents
   alone do not establish exact release correspondence. Preserve duplicate full
   identities and route collisions; changed bytes with a recomputed generated
   digest remain changed originals. Include application/recovery preservation
   when the selected populated route requires it.
5. Recheck original cut/configuration/authority freshness and publication closing
   before returning any complete observation. Loss of a required surface or cut
   cannot be turned into drift from the available fragments. Retain trusted
   recovery evidence while obeying caller disclosure and unavailable branches.

## Existing result classification

| Request | Complete qualified observation | Incomplete/unavailable observation |
| --- | --- | --- |
| status | `observed` with original layout/installation/native observation, current-installation scope only | `observation_unavailable` with the existing reason; no layout/installation/native observation payload |
| verify | `matches` after complete correspondence, or `drift` with complete original observation and differences | `observation_unavailable`; no partial native observation or correspondence payload |
| reconcile | Follow the separate original-attempt protocol | Preserve original uncertainty; status/verify cannot infer rollback or retry apply |

The recent archive probes call complete fixture mismatch an integrity failure.
For the public verification binding, complete qualified observed mismatch maps
only to its existing `drift` branch. Revoked SELECT with a readable marker maps
to `observation_unavailable`, never missing archive or matches. No new public
`integrity_refusal` variant is selected by component terminology.

## Remaining dependencies

The complete release and all seven native semantic bodies remain unimplemented.
The security owner must close original observer/current-authority, exclusions,
coherent-cut/final-freshness and publication/drain interfaces. The corrected
private pgserver16.15 runtime is not a published default, and Aurora/Lakebase need
separate native profile qualification. Truss can implement inventory collection
and expected-negative fixtures now, while keeping absent composition explicit.
Fresh install and first Python operations need not wait for a populated migration;
source/target/recipe/preservation/recovery preparation proceeds alongside them.
