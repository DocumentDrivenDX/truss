# Shared action-store registration

The private PostgreSQL 18 implementation now issues one logical action store per Truss installation. UMF exports its 25-column storage layout, including the installation and original metadata-epoch foreign keys. The packaged storage SQL is identical to that export. The native issuer allocates a distinct logical store identity and immutable guard epoch, retains the original tenant and executor identities, and stores the initial receipt atomically with registration.

`register_action_store_in_transaction(host, tx, tenant=..., registration_key=..., executor_roles=...)` runs in the caller's trusted administrative READ COMMITTED transaction and returns a pending receipt. The caller commits. `observe_action_store_in_transaction` reads the committed original receipt in a fresh READ COMMITTED transaction; the issuing transaction cannot promote its own pending registration. An exact retry returns the original receipt. A different key or changed original tenant/executor selection refuses replacement. Registration keys are privately bounded bytes, not replay namespaces.

The ordinary observer and REPEATABLE READ store-cut helper require the actual connecting native login OID to appear in the original executor inventory. Inherited privileges alone do not satisfy that check. Recovery by an actual native superuser remains explicit. Ordinary executors cannot select or insert the protected home or call the issuer. Installation verifies original columns, constraints, defaults, generated expressions, sequence dependencies, indexes, immutable trigger, native helper definitions and grants.

The basic original products workflow passed on PostgreSQL 18.6: catalog acceptance, genuine metadata-source initialization, registration, commit, ordinary observation, exact retry, connection reopen, denied ordinary storage/issuer access, then public object creation and reads. The repository test is `packages/python/tests/test_action_store_native.py`. Original receipt, artifact hashes and source hashes are retained under `evidence/action-store-20261014/`. Astra Ultra approved this scoped implementation.

`bindingCorrespondence` checks physical installation, database/schema incarnation, postmaster start, original metadata-epoch row and runtime labels. It is not full current-source admission. The context verifier is READ COMMITTED only and returns no authority. A restart conservatively fences fresh use while retaining the original receipt and identity; readmission requires explicit future work. Guard epochs never reset replay identity. Security-owned current authorization, immutable anchors, guarded permits and protected bulk execution remain separate integration work. This component is private and does not add a public release claim.
