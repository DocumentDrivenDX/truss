## Original discovery findings and current authority

The findings below preserve the initial discovery context. Later contracts/declarations address several of these shapes (including complete historical envelopes and group planning), so this list is not the current missing-work checklist. - **Catalog identity:** CONTRACT-003 names document/module/element identity but duplicate detection and `type_def` uniqueness use module/element. Weft carries owning document/revision identity. Decide a versioned document-qualified storage identity or an explicit restrictive namespace policy; do not infer ownership from display names.
- **Cross-document validity:** UMF validity is checked before Truss resolves relationships, while CONTRACT-003 itself notes the UMF resolver is document-local. A Truss provisional endpoint cannot bypass a UMF validity failure. Obtain a qualified UMF bundle contract or explicitly refuse that input subset.
- **Group locking:** sequential operations with aliases, changing endpoints and recursive deletion cannot acquire an arbitrary future lock set solely by sorting each operation. Specify preflight and revalidation plus one lock hierarchy; defer unsupported dynamic groups instead of promising deadlock freedom.
- **Replay:** journal rows alone may not reconstruct all original operation results, especially mixed no-op and changed operations. Define replay result obligations and request hash canonicalization; never assume caller hashes prove identity.
- **History/feed:** whole-record envelopes currently contain props/retained but omit edge endpoints/order and composition metadata; absent versus explicit null changes need presence evidence. Resolve before claiming reconstructible graph state.
- **Feed compatibility:** CONTRACT-006 says exactly-once position completeness and at-least-once replay; describe delivery/application separately. A new semantic record kind cannot be silently ignored by a consumer that needs it for correct state. Define snapshot/feed cut and side-record ordering explicitly.
- **Enforcement boundary:** the edge-limit primary key only constrains markers. A raw edge insert can omit markers unless a qualified integrity guard makes maintenance unavoidable. FR-14/35 require a bypass-tested guard or honest engine-only classification until that gate passes.
- **UMF semantics:** a keyed association Record does not imply endpoint-pair uniqueness, and a record-valued Field does not declare a relationship. Explicit supported bindings/refusals must preserve these distinctions.
- **Bootstrap authority:** handwritten SQL currently governs layout. Moving authority to UMF generation needs an explicit contract amendment and exact schema parity, including sequences, partitions, functions/policies, indexes, grants and initial rows. Unsupported generator stages must be reported, never patched invisibly.
- **Stale concerns:** partition-per-type, mandatory preparation and never-FOR-UPDATE wording conflict with the accepted flat layout, optional preparation and delete locks. Reconcile in place without changing concern selection.
