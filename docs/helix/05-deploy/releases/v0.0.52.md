# Truss v0.0.52 candidate

This draft records prepared metadata for `umf-truss==0.0.52`. No GitHub release,
PyPI upload, tag, or publication receipt exists. The selected local build uses
the runtime identity `truss-catalog-runtime/0.75-candidate`; its exact native
manifest SHA-256 is
`5ecb599f65d64e6656bf6c83c30cea6e2aefd488cb3fe821b749458d5e9b3522`.

## Candidate scope

Truss adds a same-session-bound feed source custody handle for one exact consumer,
epoch, checkpoint and retained feed page. Native custody rows bind the selected
runtime release, feed digest, page limits and opaque request, destination
registration and ACK-scope bytes. A same-session advisory lock marker supplies
the liveness witness; guarded SQL fences legacy ACK and consumer re-registration
while the handle is active. Connection loss releases the marker and permits
stale-row pruning. `renew` mutates custody state and requires a writable
transaction. Reconciliation is read-only and must be adopted through a
read-only transaction.

Destination registration and protected destination ACK remain external
authorities owned by Ashlar. The positive ACK in local Truss evidence is a
disposable source-fixture ACK; it is not an Ashlar or production destination ACK.

The optional query extra and retained query/disclosure archives continue to
select `weft-sql==0.4.51`, the exact compiler version admitted by the current
Truss runtime and archive identities. Weft 0.4.56 is published as
`umf-weft==0.4.56` with the `weft` import and changes module-envelope selection
for matching non-null literal defaults. It is not a drop-in update for these
frozen inputs. Adopting it requires a preserving query/disclosure archive
migration and exact corpus/runtime qualification; this custody release does
not perform that migration and does not describe 0.4.51 as the current Weft
release.

The migration index replaces an unpublished earlier `.75-candidate` endpoint
with the final custody runtime endpoint. It retains the exact accepted lineage
and adds one `.74 → .75-candidate` forward edge. The edge was applied and
verified on one local PostgreSQL 18.6 cold clone whose source profile matched
the retained R16b `.74` source. The build evidence records source, target, edge,
ACL profile, initialization capture and migration-receipt hashes.

## Qualification limits

The candidate has focused source tests, independent America/New_York and UTC
target captures, a disposable local lifecycle, and one native `.74 → .75`
migration receipt. This does not establish hosted Linux release CI, public
package installation, external destination ACK, Ashlar production custody, or
additional platform/runtime qualification. The runtime manifest deliberately
retains its candidate release identity pending separate review.

The draft remains `status: draft` until Sol reviews the integrated source delta,
the selected local universal wheel, and the release metadata. Publication must
follow the authorized local publishing workflow and use the exact reviewed
immutable tag; local wheel preparation does not publish or authorize those steps.
