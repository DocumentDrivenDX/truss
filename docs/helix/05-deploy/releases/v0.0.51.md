# Truss v0.0.51 candidate

## Release scope

The reserved next distribution is `umf-truss==0.0.51`, replacing the PyPI name
`truss-toolkit` for future deliveries. The `truss` Python import, CLI entry
points and runtime protocols retain their identities. This is source preparation,
not a qualified or published release. No tag, archive digest, native test result
or registry upload is claimed for this candidate.

The preparation starts from main
`72497d1b97a86bec41e445f9ba1235e999835de5`, containing the published 0.0.50
runtime and its PyPI proof. Tag, accessible release and PyPI checks found
0.0.51 unused on 2026-10-26. The later exact release source and artifact tuple
must be recorded by its real producer; this document does not embed its own
commit hash.

## Audience and channels

Python consumers will receive the new distribution through GitHub and PyPI
after qualification. Host applications continue to own connections, transactions,
authorization and admission of the actual installed dependency cohort.

## Changes and required actions

The candidate changes distribution/version metadata and prepares the future
release and OIDC publishing paths for `umf_truss-...` archives. Historical
`truss-toolkit` names, files and receipts retain their original meaning.

When released and admitted by the consumer, dependency declarations must use
the new distribution name while retaining `import truss`. Use a fresh
environment rather than installing both distributions together: they provide
the same import tree. This candidate does not update a consumer's lock or
claim that a new public installation is already available.

## Migration and runtime policy

Only the latest application runtime is supported. Every admitted database
lineage must retain its explicit forward path to the latest runtime; old
application runtimes do not remain supported. Pre-0.10 UMF sources and downgrade
paths remain unsupported. Startup performs no automatic upgrade or reset.

This naming preparation changes no native SQL, runtime manifest, embedded UMF
assets, migration recipe or source-wheel identity. A package rename must not
fabricate a physical migration edge. Actual existing-current verification and
all populated predecessor preservation cases remain required for the final
installed candidate. Its receipt must identify the new archive and latest
installed distribution, while source fixtures retain their original wheel names.

## Qualification and publication prerequisites

The intended compiler dependency is the actual public `umf-weft==0.4.55`
cohort at `ea0fef0209aaf8e08ef165b6afe00b408873354f`. Its publication alone does
not admit it into Truss. Current compiler/dependency/cohort pins remain at their
existing selection during this preparation. Changes to those pins and Core
consumption wait for the owning session's actual Core 0.10.3 tuple and the
corresponding integration qualification; no unpublished Core/SDK artifact is
substituted.

The final wheel and sdist must pass the existing Linux-only release gates:
exact source payload checks, all retained forward-migration lineage cases,
the independent HF corpus, managed-grant checks and the installed native
consumer gates. Historical Mac, managed-service and old archive results do not
qualify this cohort. Any claim beyond the observed Linux profile needs its own
fresh evidence.

Stack owns the package-specific `umf-truss` publisher registration. It has not
yet been accepted; the existing `truss-toolkit` grant does not transfer.
Publication requires that actual grant, the new source/tag/archive tuple,
verified immutable release assets, Actions OIDC upload, public served-byte
comparison and a fresh public-index consumer. No local registry upload is
authorized by this preparation.

## Known issues and hold guidance

Keep consumers at their qualified pins until the complete new cohort is
available and their owning admission gates pass. The pending Core tuple,
compiler admission, publisher registration and native/public qualification
are open prerequisites, rather than completed tests or compatibility claims.
