# Truss v0.0.55 release candidate

## Release scope

The local `umf-truss==0.0.55` candidate adds a bounded, optional
`operation_timeout_ms` argument to `CatalogReferenceAssembly.install_in_transaction`.
It lets a caller select a longer deadline for that one fresh-install operation
when the adopted host's default is too short. The default continues to use the
host's configured operation deadline.

The override is limited to 1–180000 milliseconds. PostgreSQL's statement timeout
remains independently capped at 60000 milliseconds, and an already-active outer
host operation deadline remains the tighter bound. Later operations continue to
use the host's configured default. The override requests cancellation through
existing containment; it does not establish server termination, rollback,
transaction settlement or safe connection reuse.

`43b863053925d376030792c922b7098134890853`:

## Highlights

- A caller may bound one fresh catalog-install operation up to 180 seconds.
- The ordinary host deadline and later operations retain their existing
  behavior.
- Focused timeout tests and the selected fresh Truss source/ACK path passed
  locally; hosted and full-suite gates are not claimed.

## Changes and fixes

The change affects Python hosts that install a fresh catalog using
`CatalogReferenceAssembly.install_in_transaction`. It adds no database
migration, changes no native SQL or catalog manifest, and leaves later host
operations on their existing deadline. The 0.0.53 fresh-install-only baseline
and its refusal of historical upgrades/recovery remain in force.

There are no breaking changes in the selected local scope. There is no new
operator action for existing installations. This version is not yet available
through public package channels; do not install it from PyPI.

## Local qualification status

The focused timeout test module passed all four tests against the checked-out
source under Python 3.12.14 from the selected local 0.0.55 runtime environment.
The tests cover the unchanged default, explicit bounded forwarding, invalid
values refusing before host work, and the one-operation host path. See the
[focused test receipt](../evidence/truss-0.0.55-local-qualification/focused-timeout-tests.json).

Ashlar's R61 fresh-source qualification used the exact 0.0.55 wheel with public
Truss installation, acceptance, source/consumer, feed and protected ACK APIs.
The local flow produced the four-role `ashlar-delta/0.4-xxhash64` publication,
performed native Weft reads, acknowledged the continuation, and captured the
original owner graph release and custody. A separate GraphFrames-only action
validated those retained bytes: six nodes, three edges, full-row parity and the
directed two-hop counts. The exact closeout and GraphFrames report are retained
in the [local qualification evidence](../evidence/truss-0.0.55-local-qualification/README.md).

This is a scoped local result, not a full Truss-suite or general platform
qualification. The source worker exited after its GraphFrames custody adapter
refused the Truss custody format; the reviewed GraphFrames-only rerun passed
against the immutable retained release/custody bytes. The closeout records this
composed evidence and its limits. Focused timeout tests and this Ashlar workflow
do not establish backend termination, arbitrary cancellation latency, general
transaction recovery or safe connection reuse.

Hosted release workflows, the full Truss release suite, a public-index consumer,
and PyPI/GitHub publication are not claimed here. Release publication remains
pending the remaining independent release gates.

## Migration, hold and support

There is no new migration. Startup does not reset or upgrade an existing
database. Preserve existing environments and use only the separately qualified
fresh-install procedure; historical upgrade and receipt-recovery paths remain
unsupported under the 0.0.53 baseline.

Hold adoption if an active outer deadline is shorter than the requested
installation window, or if the host cannot contain and settle a timed-out
installation. Do not interpret cancellation request or client-side timeout as
proof that PostgreSQL stopped or rolled back. The
[install-deadline handoff](../../04-build/local-deadline-installation-handoff.md)
retains the operation and recovery boundaries.
