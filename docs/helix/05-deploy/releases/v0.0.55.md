# Truss v0.0.55 candidate

This document records local candidate scope for `umf-truss==0.0.55`. The
candidate is not tagged, published, or qualified for general release.

## Candidate scope

The candidate adds an optional `operation_timeout_ms` argument to
`CatalogReferenceAssembly.install_in_transaction`. The default remains the
adopted host's configured operation deadline. A caller may set this one fresh
installation operation's host deadline up to 180000 milliseconds. The normal
host operation deadline and all later operations remain unchanged.

The native PostgreSQL statement timeout remains separately capped at 60000
milliseconds. An already active outer host operation deadline remains the
stricter bound. The longer install deadline requests cancellation through the
existing host containment path; it does not prove backend termination,
transaction rollback, or safe connection reuse. Existing recovery and caller
settlement requirements remain in force.

## Qualification status

The focused Python unit tests for the timeout argument and host forwarding
passed locally. The intended Ashlar .55 fresh-source qualification remains in
progress; this candidate has no release artifact, CI qualification, PyPI
publication, or tag.

The change adds no migration, does not modify the fresh-install catalog
manifest or native SQL, and does not alter the 0.0.53 fresh-install baseline.
