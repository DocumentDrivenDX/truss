# Truss v0.0.53

## Release Scope

The candidate `umf-truss==0.0.53` completes the hosted release and registry
delivery of the source-custody runtime introduced in 0.0.52. Release date and
publication remain pending the exact-tag Linux gates. The existing immutable
0.0.52 archives remain unchanged; they lack the identity asset required by the
registry publisher.

## Audience and Channels

Python embedders and operators receive the wheel, source archive, release pins
and qualified Linux receipts through GitHub Releases and PyPI after publication.
The import namespace remains `truss`.

## Highlights

The source-custody handle binds one feed consumer, epoch, checkpoint and retained
page to a same-session advisory-lock marker. Host applications own the
authenticated connection and transaction. Destination registration and protected
destination ACK authority belong to the consumer.

## Changes and Fixes

The boundary map now accounts explicitly for the native host's cryptographic
session-marker randomness. The source-custody SQL, migration manifests,
runtime identity `truss-catalog-runtime/0.75-candidate`, embedded owners and
`weft-sql==0.4.51` compiler cohort retain their 0.0.52 identities. The independent
conformance roster selects the new toolkit package version.

## Breaking Changes and Required Actions

There is no new runtime migration relative to 0.0.52. Install the renamed
distribution in a clean environment:

```sh
python -m pip install 'umf-truss[native,query]==0.0.53'
```

The old `truss-toolkit` distribution provides the same import tree and must not
coexist with `umf-truss` in that environment.

## Migration or Rollback Guidance

Earlier installations must use the admitted offline migration graph, including
the exact `.74` to `.75-candidate` source profile. A refusal is a hold condition;
do not bypass source identity checks. Keep the previous environment and source
backup available. Package rollback does not reverse a committed database migration.

## Known Issues and Support

The runtime remains a candidate. Local fixture ACK evidence does not establish
Ashlar or production destination authority. Weft 0.4.56 changes the distribution
and selected envelope semantics; adoption requires separate archive and native
qualification. Hosted release receipts qualify Linux x86-64 only. Managed
Lakebase, broader platform support and Ashlar acceptance remain separate gates.
