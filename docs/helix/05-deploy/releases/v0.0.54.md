# Truss v0.0.54

## Release Scope

`umf-truss==0.0.54` adds the standalone `LocalTimestampValue` Python carrier.
Temporal native storage, acceptance and query execution remain unqualified and
unavailable through the current value profiles. Delivery requires complete
exact-tag Linux qualification, verified GitHub/PyPI bytes and a fresh public
consumer. The immutable 0.0.53 release remains unchanged.

## Audience and Channels

Python embedders receive a wheel and source archive through GitHub Releases and
PyPI. The import namespace remains `truss`; native and query dependencies retain
their existing exact pins.

## Highlights

```python
from truss import LocalTimestampValue

local = LocalTimestampValue(text='2024-02-29T23:59:58.000001')
assert local.kind == 'localTimestamp'
```

The immutable carrier retains exactly 26 ASCII characters in
`YYYY-MM-DDTHH:MM:SS.ffffff` form. Gregorian dates and clock fields are checked;
offsets, zones, leap seconds and different fractional precision refuse. A civil
local value never acquires a timezone or becomes the existing timestamp carrier.

## Changes and Fixes

Existing `ExactValue`, presence, container and import profiles continue to
refuse the new carrier. Existing timestamp text retains its original precision
and offset spelling. The native runtime, ABI1.2, embedded owners and
`weft-sql==0.4.51` cohort are unchanged.

The [current temporal integration plan](../../04-build/temporal-current-baseline-plan.md)
records the real UMF/Weft owner interfaces and remaining native/installed/browser
work. The new release gate verifies the standalone carrier and its refusals from
the installed wheel; its receipt is distributed with the release. The public
PyPI consumer also checks the exported constructor and closed legacy profiles.

## Breaking Changes and Required Actions

Install the exact distribution in a clean Python environment:

```sh
python -m pip install 'umf-truss[native,query]==0.0.54'
```

Do not pass local carriers to current storage, mutation, import or query APIs.
They remain outside those accepted profiles. The old `truss-toolkit`
distribution must not coexist with `umf-truss`, because both provide `truss`.

## Migration or Rollback Guidance

The 2026-11-02 fresh-install baseline remains in force. Historical installation
upgrades and receipt recovery remain unsupported. There is no new native
migration, automatic reset or data conversion.

Preserve existing environments, data and backups; use only separately qualified
rebuild procedures. The original
0.0.53 package remains available for rollback of the Python package change.

## Known Issues and Support

The local carrier is a prerequisite for a future temporal integration, not
evidence of native temporal support. Supporting Field admission, guarded source
lowering, target execution and exact owner cohort acceptance remain open.
Hosted native qualification covers Linux x86-64. Managed Lakebase and broader
platform or downstream acceptance remain separate gates.
